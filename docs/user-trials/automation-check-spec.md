# M14 浏览器自动化可执行检查规格

M14 已在专属 `scripts/m14/` 与 `tests/m14/` 落地执行器，不修改 M13 脚本或测试。浏览器自动化必须驱动真实页面入口，不能直接调用内部
workflow 代替用户路径。自动化不是用户研究，也不得生成虚构参与者、观察记录或满意度数据。

## 运行前提

- 使用 M11–M13 合流后的候选构建和独立浏览器会话/端口。
- 生产式运行锁定真实 DeepSeek 与真实 Sepolia RPC；凭据仅由受控环境注入，不写入截图、trace 或报告。
- 公共发布和写链默认关闭；本规格不授予相关权限。
- 准备 R1 固定基线和 R2 独立输入。R2 必须记录生成/组装方法和独立 RPC 预检，不能只把 fixture 改名。
- 每次运行使用唯一工作区 ID，恢复场景除外；开始前确认没有前次 session/storage 泄漏。

## 建议产物接口

自动化实现应接受运行时参数，而不是在脚本中硬编码唯一案例：

```text
--base-url <合流版入口>
--workspace-id <唯一匿名 ID>
--report <UploadedReport JSON 路径>
--scope <核验范围文本或结构化输入>
--expected-outcome <PASS|FAIL|INCONCLUSIVE>
--evidence-dir <本次证据目录>
```

凭据、完整环境变量和私有报告不得作为命令行参数或写入证据目录。已实现命令和实测边界见
[2026-10-07 实测快照](readiness-evidence-2026-10-07.md)。

## 必做流程

### A. 冷启动独立输入

1. 创建全新的浏览器上下文，清空 cookie、local/session storage，不复用已登录状态。
2. 打开 `--base-url`，断言环境标签为真实 Sepolia 路径且页面无前次任务数据。
3. 上传 `--report`，验证页面显示内容哈希且没有把本地签名描述为作者认证。
4. 输入 `--scope`，生成候选并断言链、代币、账户和区块与测试参数一致。
5. 在确认前尝试执行，断言入口不可用；确认后记录任务指纹。
6. 发起核验，等待终态；保存结论、金额、Finding、RPC 诊断及至少一个完整事件键。
7. 将页面结果与事先独立 RPC 预检比较；不由 UI 文本本身生成 expected value。

### B. 修复前后与只追加历史

1. 用错误版报告完成 Attempt 1，断言 `FAIL` 和预期 Finding。
2. 上传修正版完成 Attempt 2，断言 `PASS`。
3. 断言两个 attempt、提交哈希和回执均可分别读取，Attempt 1 未被覆盖。
4. 尝试第三次执行，断言被阻止且没有新增存储记录。

### C. 全新会话恢复

1. 保存工作区 ID、任务指纹、attempt ID 和回执哈希后关闭整个浏览器上下文。
2. 创建另一个干净上下文，只输入相同工作区 ID。
3. 断言恢复的是同一任务和历史 attempt，哈希逐项一致。
4. 对上传来源任务，断言补交前要求重新选择修正版，不静默切换到演示服务。

### D. 输入与证据异常

1. 对每类 N1 非法文件单独执行上传，断言错误可见、页面不中断、无 attempt/回执副作用。
2. 用可控 adapter 或网络拦截制造 RPC 超时/缺页；断言 `INCONCLUSIVE`、诊断可见且不回退 fixture。
3. 制造来源冲突；断言来源标签分别保留，不能得到确定性 `PASS`/`FAIL`。
4. 中途刷新、关闭标签页或重启应用后执行恢复检查；不得因恢复而重复提交或覆盖历史。

### E. 可访问性与响应式

在 1440×1000、390×844、759px、761px 和 200% 放大重复关键路径。采集 `scrollWidth` 与 `innerWidth`，检查页面级无水平溢出；
资金流图或 JSON 可在自身容器滚动。验证键盘焦点、主操作唯一性、错误文字持续可见和 Finding 证据可达。

## 稳定定位与等待

- 优先用可访问名称、标签和角色定位，不依赖随机 class 名、像素坐标或文本出现顺序。
- 只等待明确 UI 状态或网络终态，不使用固定长时间 sleep 代替条件等待。
- 真实 RPC 的期望金额和事件集合在运行前由独立预检产出并冻结；UI 自动化不得自行重算后再与自己比较。
- 截图之外必须保留结构化断言；视觉证据不能替代结果、存储和哈希校验。

## 失败与重试

- 浏览器、模型或 RPC 失败按实际状态记录，不把重跑后的成功覆盖首次失败。
- 自动重试只适用于无副作用的页面加载或只读请求，最多按项目既有策略执行；未知提交状态不得重发。
- 每个失败保存最小 trace、步骤和脱敏错误。修复后用同一输入和步骤复测，并保留前后两次记录。

## 完成输出

每次运行必须生成一份符合[验收证据模板](evidence-template.md)的记录。只有矩阵全部通过时，才能声称“支持范围内技术自助路径
已验证”；始终同时注明“未进行真实用户测试，浏览器自动化不等于真实用户验证”。
