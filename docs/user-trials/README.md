# M14 无用户参与的用户就绪验收索引

`docs/user-trials/` 是已分配的历史目录名；本目录不组织真实用户试用，也不包含招募、访谈、观察或受访者记录。
M14 在当前约束下只验证：支持范围内的未来真实用户能否依照公开说明，用自己的合规 JSON 报表在全新浏览器会话完成
“上传→确认范围→真实链上核验→定位差异→修复或恢复”。

## 交付材料

- [用户自助操作说明](self-service-guide.md)：不依赖固定样例的准备、上传、确认、核验、解释和恢复步骤。
- [用户就绪验收矩阵](readiness-matrix.md)：真实链上端到端、独立输入、全新会话、异常恢复和响应式检查。
- [自动化可执行检查规格](automation-check-spec.md)：供 M13/集成线实现与运行浏览器自动化的前置条件、场景和判定。
- [验收证据模板](evidence-template.md)：只记录实测事实，不创建虚构用户、观察或访谈数据。
- [2026-10-07 实测快照](readiness-evidence-2026-10-07.md)：已完成的浏览器检查及未齐项。

可执行入口位于 `scripts/m14/check_readiness.py`，证据保真测试位于 `tests/m14/`。本次按用户暂停自动操作的要求收口，
不追加浏览器、故障或外部验证；恢复入口保留供以后明确恢复操作时使用。

## 结论边界

- 自动化与真实链上实测可以证明技术路径可操作、状态语义稳定、异常可恢复。
- 自动化不能证明真实用户理解、首次使用成功、市场需求、会计合规、生产安全或商业化完成。
- 当前没有真实测试用户，因此不得使用“用户验证通过”“至少两位用户完成”等表述。
- 用户明确本轮不做真实用户测试；缺少参与者不是提交、合并或部署的阻塞，技术未验收项仍保留。
- 固定样例只可作为可重复回归基线；最终就绪判定还必须包含独立输入和真实 Sepolia 证据。
- 正式验收等待 M11–M13 合流版本，不依赖招募、访谈、内部人员或用户提供参与者。

## 数据与安全边界

- 只使用公开 Sepolia 链上证据和无敏感信息的测试报表；不得使用真实客户报表、主网资金、钱包连接、密钥或凭据。
- 上传仍受现有 `UploadedReport` 契约约束：严格 UTF-8 JSON、最大 1 MB、最多 200 条记录、最小单位整数字符串。
- 本地上传身份只说明系统接收了文件，不认证报表作者。
- RPC 失败、缺页、重组或证据冲突必须得到 `INCONCLUSIVE`，不得伪装为 `FAIL` 或 `PASS`。
- 公开发布和写链需要单独显式授权，不属于本验收包自动执行的动作。
