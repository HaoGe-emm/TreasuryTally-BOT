# M13 三分钟路演排练与网络故障预案

## 适用范围

本文只覆盖 M13 的路演预检、现场时间线、独立会话复核和网络失败处置。它复用现有 `UploadedReport`、公开回执内容哈希与
确定性重放能力，不创建第二套回执格式，也不替代 M9 修订链或 M10 历史事实投影。

当前分支尚未包含 M9/M10、M11 真实案例和 M12 页面合流结果。因此本文中的三轮记录表是待执行模板；没有填写实测时间、
证据和结果前，不得宣称 M13 已达到“连续三次三分钟走通”的退出条件。

本阶段没有真实用户或真实测试用户，也不依赖招募、访谈、内部人员或评委参与。验收只证明支持范围内的未来用户可以按页面与
文档自行操作：使用非固定的严格 JSON 输入、真实链上只读证据、全新浏览器/进程和异常恢复完成技术闭环。自动化通过不等于
真实用户验证、可用性研究、市场需求或商业化成立。

## 安全边界

- 预检和独立验证均为只读，不发布文件、不写链、不部署，也不读取私钥或 API key。
- 公开上传和 ERC-8004 写入必须分别取得当次显式授权；预检通过不构成授权。
- `READY` 仅表示给定输入通过本地契约、入口可访问且目标公开回执可重放，不表示 M9 修订链或生产外部服务已经验收。
- 网络超时、DNS/TLS/HTTP 失败或公开字节无法取得统一为 `INCONCLUSIVE`，不记为服务失败，不进入负面信誉。
- 团队构造报表、真实 Sepolia 证据和标注日期的既有实测材料必须分别标注，不得混称为同一事实。
- 输入文件只要符合 `UploadedReport` 契约即可参与预检；不得把仅能识别仓库固定样例视为自助可操作。

## 合流后的预检命令

使用集成负责人确认的 M11 错误版/修正版路径、生产入口和已发布 PASS 回执。内容哈希必须来自发布结果或另一可信渠道，不能从
刚下载的同一份未知字节自算后充当外部期望值。

```powershell
D:\HACKTHON\.venv\Scripts\python.exe scripts\m13\check_demo.py preflight `
  --app-url "https://creatoros.top/trust-receipt/" `
  --faulty-report "<M11错误版UploadedReport路径>" `
  --corrected-report "<M11修正版UploadedReport路径>" `
  --receipt-uri "<已授权公开的PASS回执HTTPS地址>" `
  --expected-content-hash "0x<64位sha256>"
```

退出码与含义：

| 退出码 | `overall_status` | 处理 |
|---:|---|---|
| 0 | `READY` | 可以开始排练；仍需在页面实际走完整主线 |
| 1 | `FAILED` | 输入、哈希、授权、对象关系或重放结果有确定性错误；先修复，不演示 |
| 2 | `INCONCLUSIVE` | 外部网络证据不可取得；启用下方弱网预案，不评价服务 |

脚本只接受远端 HTTPS；为本机隔离测试允许 `localhost`、`127.0.0.1` 或 `::1` 的 HTTP。

## 三分钟主线

建议演示前已打开应用首屏，但不要预先完成业务动作。时间预算从讲解价值开始计时。

| 时间 | 操作 | 必须让观众看到的证据 |
|---|---|---|
| 0:00–0:25 | 说明收到外部链上拨款报表并加载错误版 | “团队构造报表”标签、固定 Sepolia 范围、报表原始声明 |
| 0:25–0:50 | 确认链、代币、资金账户、收款地址、区块和排除规则 | 确认后范围与 `spec_hash` 不再静默变化 |
| 0:50–1:20 | 执行首次核验 | `FAIL`、精确差额、可定位交易、服务声明与链上参考来源分离 |
| 1:20–1:50 | 上传修正版作为唯一一次补交 | attempt 1 仍在；attempt 2 追加，不能覆盖首次失败 |
| 1:50–2:10 | 展示修复结果 | `PASS`、金额/数量、修订关系；M9 合流后展示父回执与 supersedes 链 |
| 2:10–2:30 | 经当次授权公开 | 明确区分公开文件与链上状态；未授权或未确认时如实显示 |
| 2:30–3:00 | 在独立会话复核 | 内容哈希、receipt/task/object links、确定性结果重放均有效 |

自动化备选 B：测试在一个新的独立任务中从完整报表删除或改动一条记录，确认结果变为 `FAIL`，再恢复完整报表得到 `PASS`。
该任务仍只有两个 attempt，不能为了演示绕过补交上限。标准路径与备选路径不得共用已经消耗两个 attempt 的任务。

## 独立会话复核

在新的终端进程和新的浏览器隐私会话中执行，不能复用应用工作区、聊天历史或私有回执目录。先从公开页面复制 URI 与可信内容
哈希，再运行：

```powershell
D:\HACKTHON\.venv\Scripts\python.exe scripts\m13\check_demo.py receipt `
  --receipt-uri "<公开PASS回执HTTPS地址>" `
  --expected-content-hash "0x<64位sha256>" `
  --expected-outcome PASS
```

保留 JSON 输出中的 `receipt_id`、`receipt_hash`、`task_hash`、`outcome` 和 `content_hash`。M9 合流后还需从其公开验证入口分别以
URI、receipt hash、task hash 或 feedback transaction 进入并核对同一对象关系；这部分不能由当前基线脚本臆造。

## 网络失败预案

1. 任一实时网络步骤失败时停止宣称“现场验证成功”，保存脚本的 `INCONCLUSIVE` 输出或页面证据不足状态。
2. 口头说明：“当前无法取得完整外部证据，所以系统不判断服务好坏；下面展示的是 `<日期>` 已完成的脱敏实测材料。”
3. 展示预先准备且标注日期、网络、交易/区块、公开 URI 与哈希的既有材料；不得把录像、截图或缓存说成当场实时结果。
4. 仍可用本地文件执行只读重放，但必须称为“既有公开字节的离线复核”，不能替代当场公网可达性证明：

```powershell
D:\HACKTHON\.venv\Scripts\python.exe scripts\m13\check_demo.py receipt `
  --receipt-file "<预先保存的公开回执文件>" `
  --expected-content-hash "0x<64位sha256>" `
  --expected-outcome PASS
```

5. 网络恢复后重新运行在线命令。不得修改期望哈希、删除失败 attempt、改用 fixture 冒充实时 Sepolia，或把
   `INCONCLUSIVE` 改写为 `PASS`。

## 三轮自动化技术排练记录

每轮由自动化使用独立任务/工作区、新浏览器上下文和新验证进程执行，无需测试人员参与。计时包含完整页面操作与结果读取，
不只记录脚本耗时。该记录只证明技术路径，不得称为真实用户测试。

| 轮次 | 日期时间 | 路径 | 总时长 | attempt 1 | attempt 2 | 公开状态 | 独立验证 | 网络状态 | 证据位置 |
|---:|---|---|---:|---|---|---|---|---|---|
| 1 | 2026-10-07 | 重新确认排练 | 75.438s | FAIL | PASS | 未新发布 | 既有公开回执 | 真实调用 | `.tmp/m13-confirmed-rounds/`（M13 工作区） |
| 2 | 2026-10-07 | 重新确认排练 | 74.906s | FAIL | PASS | 未新发布 | 既有公开回执 | 真实调用 | `.tmp/m13-confirmed-rounds/`（M13 工作区） |
| 3 | 2026-10-07 | 用户停止后中断 | 未完成 | 不计通过 | 不计通过 | 未新发布 | 无最终结果 | 不计通过 | 退出码 1，无最终 results.json |

每轮结束检查：首次结果未被覆盖、最终 PASS 有公开字节与可信哈希、独立会话输出为 `READY`、总时长不超过三分钟。任一项缺失
则该轮不计入连续三次通过。

前两轮只说明已运行技术路径，不证明新任务公开发布；本组不满足连续三次完整退出条件。此前另一组为 PASS / FAILED / PASS。
