## M13/M14 验收条件

1. 空工作区的 A/B 均为零条已核验历史、最近交付暂无；不得把没有证据解释为 PASS/FAIL。
2. A 首次 FAIL → B 第二次 PASS/FIXED：A 的失败数 1、修复成功数 0；B 的失败数 0、修复成功数 1。
   各有一个原始交付回执，不能把 B 成功记给 A。
3. 逐项来源可看到完整回执哈希；“查看来源回执与父版本内容”选择 B 原始回执后可看到 A 原始父回执，
   A 身份与 FAIL 不被覆盖。组件 rerun 后内层折叠区若收起，须重新展开检查内容。
4. 只有原始不可变 `attempt-N.json` 参与计数；M6 重复发布和 publication 状态快照不算新增交付。
   M9 公开历史包重新绑定的公开哈希与本地原始哈希不混用。
5. 缺真实父链、身份/任务/版本冲突或篡改时排除该任务，展示中性 INCONCLUSIVE 诊断。
   无版本文件的旧任务只在内存从实际回执重建，不写入版本文件。
6. 证据不足只增加无法判断，不增加失败数。人工选择 B → 确认 → 开始下一任务 → 确认范围后仍选择 B，且允许用户改选。
7. fixture 故障为团队模拟，页面必须明确本地事实不代表第三方公开信誉或链上反馈确认。
