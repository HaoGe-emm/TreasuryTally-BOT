# M11 真实案例工作包 A 交接

## 结论

工作包 A 已在不修改领域模型、Schema、页面或公共 wiring 的前提下，准备一组“团队构造报表 + 真实 Sepolia 交易”的固定案例。
错误版严格 JSON 漏报唯一符合任务范围的事件，修正版恢复该事件。现有上传服务入口在固定证据和实时 Sepolia RPC 两条测试路径中
均得到 `FAIL → PASS`，保留两个 attempt 与两份本地回执。

这不代表 M11 整体完成：示例加载/下载、页面入口接线、浏览器联调、公开发布和新会话公开验证仍由 B/C/集成负责人负责。
本工作包没有公开上传、部署、写链或读取任何私钥。
本次没有真实用户或测试用户参与；自动化与真实链上端到端证据只证明技术路径，不等于真实用户验证。

## 工具与接口

只读预检入口：

```powershell
D:\HACKTHON\.venv\Scripts\python.exe scripts\m11\preflight.py --rpc-url <SEPOLIA_RPC_URL>
```

也可显式注入 `M11_RPC_URL`，其次读取进程中的 `ETH_RPC_URL`。脚本不读取 `.env`，不需要模型、钱包、测试币或写权限。
缺少 URL 返回 `BLOCKED`；RPC 不可用、未确认范围、链上清单与固定证据不一致时以非零退出码返回 `INCONCLUSIVE`，不会把失败
伪装成案例 `FAIL`。成功输出包含分页数、原始/范围内事件数、整数金额、事件键、报告声明和公开浏览器链接。

第二组通过同一预检入口执行：

```powershell
D:\HACKTHON\.venv\Scripts\python.exe scripts\m11\preflight.py `
  --rpc-url <SEPOLIA_RPC_URL> --case-manifest independent-case.json
```

`load_case_bundle(Path("fixtures/m11"), manifest_filename="independent-case.json")` 读取相同 `CaseBundle` 接口。
M12 可从其 `.task` 取范围字段构造现有 `TaskSpecCandidate`，用户显式确认时重新生成任务 ID、确认时间和指纹；示例已确认任务
本身不替代用户确认。路径仍须在案例根目录内，不能用 manifest 跳出该目录读取其他文件。

通用只读核验入口不读取固定案例的预设结论，接受任意支持范围内、哈希有效的 `TaskSpec` 与严格 `UploadedReport`：

```powershell
D:\HACKTHON\.venv\Scripts\python.exe scripts\m11\evaluate_report.py `
  --rpc-url <SEPOLIA_RPC_URL> `
  --task-spec <TASK_SPEC_JSON> `
  --report <UPLOADED_REPORT_JSON>
```

结论完全由实时 `RpcReferenceEvidenceProvider` 和现有 `verify_submission` 推导。合法但不同的账户、收款方、金额、事件和报告内容
不会被固定样例的 PASS/FAIL 覆盖；错误 RPC、未确认区块、证据不完整或分页失败沿现有契约得到 `INCONCLUSIVE`。

通用入口限定 Sepolia，读取报告时先限制为 1 MB；确认数为 `0..128` 整数，单次 RPC 超时为有限正数且不超过 30 秒。
CLI 退出码 `0` 表示可靠取得 `PASS` 或 `FAIL`，`1` 表示 `INCONCLUSIVE` 或输入错误，`2` 表示缺少 RPC 配置。
`INCONCLUSIVE` 的 `ok=false`，不被自动化视为成功核验。异常输出不回显校验输入、认证信息或 RPC URL。
该通用命令是只读、无持久化的诊断入口；attempt 留档和回执仍由现有工作流完成，不另造历史格式。

集成负责人可直接消费以下稳定接口，无需修改契约：

1. 以 `fixtures/m11/case.json` 的 `reports.error` / `reports.corrected` 作为示例加载和下载来源。
2. 仍通过现有 `UploadedReportService` 接收文件；不得根据文件名或 manifest 静默改写用户上传内容。
3. 以 `task_spec` 指向的 `task-spec.json` 预填范围，但仍要求用户确认；其 `spec_hash` 已按现有 canonical JSON 规则校验。
4. 在线执行继续使用 `RpcReferenceEvidenceProvider`；`reference-events.json` 只作固定证据清单与回归基线，不能冒充当次在线读取。
5. Blockscout 仅作可选补充。RPC 不完整时必须得到 `INCONCLUSIVE`。

```powershell

  --rpc-url https://ethereum-sepolia-rpc.publicnode.com
```

结果：退出码 `0`，`status=COMPLETE`，当时 latest block `11861425`、confirmed tip `11861423`、1 页、6 条原始事件、
1 条范围内事件、金额 `180674489737`。没有交易广播。

专项验证：

```powershell
D:\HACKTHON\.venv\Scripts\python.exe -m pytest tests\m11 -m "not external" -q

# All checks passed
```

外部第二项测试实际通过 `UploadedReportService → M5Workflow → RpcReferenceEvidenceProvider` 执行错误版与修正版，得到真实
RPC 支撑的 `FAIL → PASS`、两个 attempt 和两份本地回执。离线专项测试另验证严格解析、冻结证据、确定性 Finding 和清单漂移拒绝。
唯一 warning 来自既有第三方 `websockets.legacy` 弃用提示。

通用核验器另以实时 RPC 分别执行错误版与修正版，得到 `FAIL`（`MISSING_TRANSFER`）与 `PASS`。专项测试还选择另一条事件
`0x7cdd2a07fc41fc5ad4138fbc5047c67962cf9b69d80626c6bbb41bcc01e728b2` / `log_index=61`，生成不同 treasury、recipient、
金额、任务哈希和报告。新任务在冻结证据与实时 Sepolia RPC 下均得到 `PASS`，权威金额为 `321794352786`；将事件声明金额
增加 1 最小单位后，实时结果为 `FAIL / AMOUNT_MISMATCH`，核验金额仍为 `321794352786`。

第四项外部测试以不可用 loopback RPC 地址触发实际连接失败，得到 `INCONCLUSIVE`、金额为空、参考不完整；随后用可用 Sepolia
RPC 重试同一任务/报告，得到 `PASS`、金额 `180674489737`。任务哈希和两份输入字节保持一致。该失败连接是受控网络故障，
恢复步骤真实读取 Sepolia。CLI 边界测试另验证 `INCONCLUSIVE` 非零退出、敏感错误脱敏和恢复。

本次完整质量门实测：`pytest -m "not external" -q` 为 **224 passed、13 deselected**；全仓 Ruff、`pip check`、16 份 Schema
漂移检查与 1000 物理行限制均通过。最终面向浏览器的独立输入、全新会话与异常恢复仍需集成负责人联调验收。
