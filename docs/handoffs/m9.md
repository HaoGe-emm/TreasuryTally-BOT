# M9 接口交接

本文件是针对提交 `30c13c3` 的接口操作说明，不替代根目录权威契约、测试计划或当前状态。
依赖应以已提交 SHA 合流；不要复制其他工作区的未提交文件。
`654b2e0` 的提交图包含 `30c13c3`，因此 M12 合流该 M10 提交时不必重复应用 M9。

## 页面与业务边界（M12）

M12 拥有公共页面 wiring。M9 只修改自己的核心模块与测试；发现 UI 缺陷先发具体证据给 M12，避免同文件竞争。

| 接口 | 调用与职责 |
|---|---|
| `trust_receipt.orchestration.m9.build_m9_artifacts` | `(executions, commitment_pairs, store)` 返回不可变 attempt 回执、返工包、版本链、修复对比和本地 M8 核验器 |
| `trust_receipt.m9.LocalRevisionStore` | `(directory)`；`list(task_id)` 读取并校验追加版本链；`append(revision)` 只创建不覆盖 |
| `app.m9_components` | `render_rework_package(ui, package)`、`render_repair_comparison(ui, comparison)`、`render_public_verification(ui, result)` |
| `app.m9_public.render_public_explorer` | `(ui, project_root)`；独立 `?verify=1` 路由在私有 runtime 创建前调用 |
| `app.m9_public.render_public_history` | `(ui, runtime, receipts)`；传入原始不可变回执元组，分别取得导出与上传授权 |

`M9Artifacts` 字段为 `rework_package`、`revisions`、`comparison`、`commitment_verifier`、`receipts`。
`commitment_pairs` 每项为 `(task_commitment, delivery_commitment, expected_signer)` 或 `None`。
旧 `app/m9_integration.py` 已移到 `src/trust_receipt/orchestration/m9.py`，不要恢复旧 import。
没有 execution 时返回空 artifacts；不要用空 receipts 调用历史分享 renderer。

返工包只取 FAIL 回执的 `confirmed + error` Finding；核心不会让 AI 文本改变金额或三态。
同任务最多两次 attempt，第二次不能覆盖第一次。A 失败、B 成功时，两家服务身份仍分别保留，
任务 `FIXED` 不能被解释为 A 自行修复成功。`INCONCLUSIVE` 不生成确定性负面信誉。

M6 后续 publication 快照可能改变 receipt hash。业务编排优先读取 `execution.receipt_path` 的原始不可变回执，
不可使用“最新已发布快照”的哈希替换 local revision。公开包是一套授权后重建的回执/版本哈希；两套不能混用。

## 公开包与独立核验（M13）

最小调用（`first_receipt`、`second_receipt` 必须来自同任务的原始合法回执）：

```python
from trust_receipt.hashing import canonical_json_bytes, content_hash
from trust_receipt.m9 import (
    PublicBundleResolver, PublicReceiptReference, PublicReferenceKind,
    build_public_bundle, verify_public_reference,
)

bundle = build_public_bundle((first_receipt, second_receipt), authorized=True)
payload = canonical_json_bytes(bundle) + b"\n"
location = "supplied-public-history"
result = verify_public_reference(
    PublicReceiptReference(PublicReferenceKind.URI, location),
    PublicBundleResolver(payload, location=location,
                         expected_content_hash=content_hash(payload)),
)
```

`authorized=True` 是调用方已取得完整历史分享授权的断言，不是绕过授权的开关。
仅本地合成 fixture 可在隔离测试临时目录生成。不要默认授权真实私有历史，也不要将原报告、签名或密钥写入包。
`bundle.receipts` 与 `bundle.revisions` 按 attempt 排序；revision 已绑定公开 receipt hash。
`bundle_hash` 是对象 canonical 哈希；下载文件的 `content_hash(payload)` 是精确字节哈希，二者不可互换。
末尾换行也属于字节哈希的一部分，不能下载后重排 JSON 再比较“原字节”哈希。

`PublicBundleResolver` 支持 URI、RECEIPT_HASH、TASK_HASH，默认选择最新 attempt；可传 `attempt=1` 定位首轮。
URI 的 `location` 是解析来源标签，不认证发布者身份。只有与独立已知的期望字节哈希比较，才核验该外部内容绑定。
包独自不能证明 FEEDBACK_TRANSACTION；真实事件读回必须使用只读 `ERC8004PublicResolver`。

返回 `PublicVerificationResult`，需要分别呈现三个维度：

- `status`: `VERIFIED / INCONCLUSIVE / INVALID`，公开证据核验状态。
- `outcome`: `PASS / FAIL / INCONCLUSIVE` 或 `None`，已记录规则的重放结论。
- `commitment_status`: `VERIFIED / UNVERIFIED / INVALID`；无公开 M8 承诺时保持 `UNVERIFIED`。

另有 `attempt`、`receipt_hash`、`task_id`、`service_id`、`resolution`、`checks`、`evidence_refs`、`reason`。
核验不重新抓取原始链上 Transfer，不能称为重新实时验账、作者认证或链锚已确认。
公开证据不足是 `INCONCLUSIVE`；内容/对象关系冲突是 `INVALID`；缺可选承诺不把有效重放改成负面结果。
特别地，单回执 attempt2 缺公开父证据是 `INCONCLUSIVE`，自称完整包却缺应有 revision 则是结构冲突 `INVALID`。

## 新进程命令与验收

从任意独立空 cwd 验证已下载的公开包，不需要 SQLite、原工作区、模型 key 或私有签名。
在本工作区没有独立 `.venv` 时使用主环境，PYTHONPATH 指向所验收的 checkout：

```powershell
$env:PYTHONPATH = 'C:\Users\Gzhou\.codex\worktrees\0347\HACKTHON\src'
& 'D:\HACKTHON\.venv\Scripts\python.exe' -m trust_receipt.m9.cli `
  'C:\absolute\public-history.json' --bundle --kind URI `
  --expected-content-hash '0x<exact-byte-sha256>'
```

`--kind RECEIPT_HASH --value 0x<public-receipt-hash>` 或 `--kind TASK_HASH --value 0x<spec-hash>` 可按内容定位。
单回执需 `--attempt`；attempt2 另需 `--revision`、`--parent-revision`、`--parent-receipt`。
CLI 退出码：`0` VERIFIED、`1` INVALID、`2` INCONCLUSIVE；外部读取错误可能只输出 status/reason，脚本需兼容。

可直接复现的新进程验收为：

```powershell
& 'D:\HACKTHON\.venv\Scripts\python.exe' -m pytest `
  tests/m9/test_bundles.py::test_new_process_verifies_complete_public_bundle
```

该测试在临时目录构建合成授权包，由真正 subprocess 在另一 cwd 核验；没有读取原私有数据库。
其他边界见 `tests/m9/test_bundles.py`、`test_public_verification.py`、`test_feedback_resolution.py`、`test_public_reader.py`。
动态 Sepolia 上传测试只能对调用方自己的本地测试报表进行验收，公开核验仅消费已获授权的公开字节；
不能为补测试而自行将真实报表/新历史上传公共服务器。

## 权限与待验收边界

独立 UI 网络 reader 仅接受配置范围内 HTTPS 文件或指定 IPFS gateway，超时、限 4MB、禁止重定向与凭据 URI；
CLI 是操作者主动选择本地路径或 HTTP(S) 的只读工具，不应直接作为匿名任意地址代理。
PublicBundleStore 发布路径包含上传动作，不属于普通核验；必须独立授权且 re-fetch 原字节比对后才保存 artifact。
真实 feedback 检查 RPC chain、Registry code、成功交易、确认数、canonical block、sender/event 和公开哈希；
旧 attempt2 缺父链仍不完整。新公开上传、真实密钥、写链、推送、main 合并、部署均不在本轮权限中。

M12/M13 联调至少检查：首轮失败仍可查看；第二轮失败或证据不足不显示 FIXED；不同服务归属；
单回执缺父链；损坏完整包；未知 hash；空私有会话与新进程；无历史时不显示错误的成功状态。
视觉矩阵尚需在合流页面核验 760px 两侧与 200% 放大；已有 390px 检查不能代替整个矩阵。
根目录权威文档同步和跨分支冲突交给主控；此交接不重复维护全项目进度。
