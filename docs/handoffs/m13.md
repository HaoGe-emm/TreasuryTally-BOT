## 已实现

- `scripts/m13/check_demo.py`
  - `preflight`：验证错误版与修正版均符合现有严格 `UploadedReport` 契约、两份原始字节哈希不同、应用入口可访问，并下载/重放
    一份预期结果的公开回执。
  - `receipt`：在全新 Python 进程中从 HTTPS URI 或本地既有公开文件验证精确内容哈希、公开授权、receipt/task/object links 和
    确定性三态重放。
  - 远端只允许 HTTPS；本地排练服务器允许 loopback HTTP；下载限制 2 MB，超时上限 60 秒。
  - 确定性内容/契约错误返回 `FAILED`；网络不可达返回 `INCONCLUSIVE`，并显式标记不影响服务信誉。
- `tests/m13/test_demo_check.py`
  - 真实子进程独立重放 PASS 公开快照。
  - 内容哈希不一致拒绝。
  - 网络失败为 `INCONCLUSIVE` 且无负面信誉影响。
  - loopback 服务器下的完整预检通过。
  - 非 HTTPS 远端 URI 被拒绝。
- `tests/m13/test_live_e2e.py`
  - 从真实 Sepolia RPC 的已配置交易动态构造任务与上传 JSON，不读取固定 fixture 报表。
  - 将第一条真实记录金额增加 1 最小单位后得到 `FAIL`，恢复真实记录后得到 `PASS`。
  - 使用不可达 RPC 验证外部异常稳定得到 `INCONCLUSIVE`，不映射为服务失败。
  - `FAIL`、`PASS`、`INCONCLUSIVE` 三份回执均由新 Python 进程独立重放。
- `scripts/m13/prepare_live_reports.py`：从配置的真实 Sepolia 范围生成独立错误版/修正版上传文件与范围说明，输出只进入调用者指定的空目录。
- `docs/demo/m13-rehearsal.md`
  - 三分钟主线、自动化改记录备选、独立会话命令、弱网预案和连续三轮自动化技术排练模板。
  - 明确当前没有真实用户或真实测试用户；自动化不等于真实用户验证。
